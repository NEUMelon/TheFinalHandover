## 为什么放在 UI Toolkit 覆盖层

- Demo α 的 UI 全部是 **UI Toolkit**（`UiRoot`、USS），不是 UGUI。
- 结局 `HengBoot → RulesRoll` 时，屏幕上显示的是 `EndingOverlay`：上下 110px 黑边，`.cine-log`（left 380 / top 230）里逐行显示衡的日志。四条 Rule ID 是 `.cine-rule .f-mono` 的 Label（34px），每条后面停 0.8 s。3D 场景里的 MES 屏只是冷白自发光面，没有内容，镜头也停在 N9，不会转到 N7。
- 所以玩家看到“衡的屏幕”的地方就是这一层。本组件**只在这一层加东西**：
  1. 盯住新出现的 `.cine-rule` 标签，在它第一次绘制之前，用内联样式把字色设成透明（底框和左边线照旧显示）；
  2. 在 `OverlayLayer` 最上面加一个只画点的 VisualElement（`generateVisualContent`，每个点是一个方块，四个顶点），坐标取标签的内容框，字号取标签的 `resolvedStyle.fontSize`；
  3. 动画结束后撤掉内联颜色，USS 原色在 0.2 s 内淡入（用内联 transition）。**最终画面与 Demo α 完全一样**，不引入新的 UI 方案。
- 日志节奏、文字内容、何时出现都仍由 EndingOverlay 和 EndingSystem 决定，本组件不改。

## 每条规则的时序（秒，从标签出现起）

| 时刻 | 画面 |
|---|---|
| 0–0.12 | 这条规则的手写原句以细点阵淡入（字号 = T-Hand-L 28px，颜色 C-Warm #E8B45A） |
| 0.12–0.42 | 拆开：没用上的点淡出、缩小，留下的点略往上散 |
| 0.42 + 0.08 × 字母序号（+0–0.04 抖动） | 该字母的点起飞，飞 0.26 s，略带上弧，颜色从暖黄变成冷白 C-Sys #E6F0F5；落定时闪一下 |
| 最后一个字母落定后 0.25 s | 点阵 0.2 s 淡出，原 Rule ID 字淡入 |

总长：ZHOU_LEFT 约 1.6 s，JIANGUO_GUARD 约 1.9 s。规则行每 0.8 s 出一条，所以相邻两条的动画会叠在一起，各在自己那一行播放。

映射方式：手写点和 ID 点都按 x 坐标排序，然后按比例对应，左边的笔画流向左边的字母。

## 接入 / 维护

1. 把两个 .cs 文件跟其他 Stage 3 文件一起拷进工程，不需要挂组件。关掉：`-lsbNoStage3Fx`。
2. 换成团队手写矢量化字体后：改 `gen_ruleid_dots.py` 的 `FONT_FILE`，然后运行 `python3 40_特效/stage3_RuleID重组/tools/gen_ruleid_dots.py`，会同时更新 C# 数据、JSON 和样片。脚本可以重复运行，结果不变（已验证）。
